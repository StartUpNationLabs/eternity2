## Honest negative — bitset candidates REFUTED (plan estimate was wrong)

The vol-212 plan predicted "bitset candidate intersection ~2-5×". Built it
(pmask per (side,color) ∧ avail word-walk, per-epoch piece relabeling for
tie-break randomness): **0.64× the vol-211 list throughput** (250M vs 390M
nodes/10 s, same config, same machine). Reason: the per-(color,color)
candidate lists ARE the precomputed intersection — deep-tree lists average
~1.5 entries, so the 4-word AND-walk per visit can't beat an indexed list
scan. Reverted to the list architecture, generalized: `pair_nw` +
**`pair_ne`** (boustrophedon) + singles + post-filters for 3rd/4th
constraints (bordered rim cells). Final ported engine: **0.94×** old
throughput with the new generality (acceptable; the old binary also carried
the refuted rim-supply tie-break, which is NOT ported).

Lesson for the vault: "intersection-precomputed lists beat bitsets when the
color alphabet is small and lists are short" — same family as the vol-16
LUT finding.
