## Build log (with same-day catches)

- **mini.rs** (bench-audit): parametric N×N instances via
  `generate_with_solution` + 5 hints at the E2-analog cells
  ((2,2),(n-3,2),(center),(2,n-3),(n-3,n-3) in (col,row)); band
  machinery: exact distinct-piece counts, repeats-allowed counting DP
  (column-major inclusion-exclusion contractions, fb_oracle scheme at
  NC=9), exhaustive B&B, BANDSAW MITM. All brute-force selftested
  (M0): exact counts ≡ brute, relax DP ≡ repeats-allowed brute,
  bb ≡ brute min, bandsaw ≡ bb.
- ★ **M0 catch #1 — shuffled-pieces rot table**: `puzzle.pieces()`
  iteration order ≠ piece id for GENERATED puzzles (the generator
  shuffles); indexing the rotation table by iteration order scored
  the canonical solution at 30 breaks. The E2 16×16 bins never saw
  this (loader ids are sequential). Fixed: index by `p.id`.
- **Column-major band enumeration is load-bearing**: row-major
  enumeration of a free-north band is ~1e8× wider (a full free row
  before any vertical constraint binds); column-major lets the
  vertical coupling prune at every column. Same collapse the
  vol-217 program rests on, now inside the band machinery.
- **BANDSAW restructure (pre-measurement)**: bottom halves are
  enumerated PER TOP-MASK GROUP from exactly the complement pool
  (BACKLOG design (b)/(c)) instead of globally over the full pool —
  the global variant's bottom tree does not collapse (free-north,
  40-piece pool). Join = interface vectors within each group.
- ★ **Exhaustive B&B at budget b* is itself expensive at 10×10**:
  the alien-frontier M0 variant (b* high) blew through 600 s without
  exhausting — the budget-bounded tree is comparable to the relaxed
  count. Replaced with 1–2-column frontier corruptions in M0; the
  REAL exhaust-rate question is exactly what prereg M2 gates on.
- **mirror_gen** (official E2): broken-top stage-1 generator, rows
  0–4, SOTA-cell-mapped masks (469/470 attribution converted to
  cell-pays-N+W convention; 469 has a double-payer at (4,14), 470 at
  (2,10)).
- ★ **Catch #2 — the clue wall at d34**: a naive row-major DFS over
  rows 0–4 stalls for SECONDS at the (2,2) clue cell (pos 34) — DFS
  exhausts the entire subtree below an unlucky rows-0–1 prefix
  before revising the cells the clue actually depends on. Control
  arm passed only via restart luck; mask arms never. Fix:
  clue-compat pre-filter — cells directly N/W of a forced cell only
  admit candidates exposing the matching color (zero completeness
  loss). All 5 arms then bank 56 tops in 2–6 s.
