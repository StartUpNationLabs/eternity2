# Vol-184 — LIGHTHOUSE: Bidirectional Row-Build with Meeting Interface

Theme: build top-down rows 0..M and bottom-up rows 15..M, meet at row M. Each direction gets the "easy" rows; the interface row M is constrained from both sides.

Status: **refuted** — MERGE fails. 0 valid pairs across configurations.

## What was attempted

1. **v2** (independent beams): run top-down beam → K top-states; run bottom-up beam → K bot-states; merge constrained by interface row M.
   - Pieces must be disjoint between top and bottom halves.
   - Top's row (M-1) S-edges must match bot's row M N-edges.
2. **v3** (per-state bottom-up): for each top-state, run a dedicated bottom-up beam using ONLY pieces NOT in top.used. Guarantees disjointness; 8× compute cost.

## What was measured

- **v2**: 0/1024 valid pairs at K=32 — independent beams pull from the same promising piece pool; disjointness constraint nearly always fails.
- **v3**: 0 valid full boards even with per-state bottom-up. Interface 16-edge match at row M is too tight: the bot-beam's row M N-edges essentially never match top's exact S-edge sequence.

## What was refuted

- "Bidirectional row-build with row M as a meeting interface is feasible at K ≤ 300" — refuted.
- The interface constraint is structurally as tight as a full bipartite matching at row M — same difficulty as the V183 row-10 wall, just relocated.

## What was kept

- v2/v3 code (`scripts/v184_lighthouse/build_bidirectional2.py`, `build_bidir_v3.py`).
- Lesson: meeting-in-the-middle on a constrained edge-coloured grid needs much larger K or relaxed interface (allow some mismatches, then ALNS-repair).
